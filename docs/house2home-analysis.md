# House2Home Nashville 拆解（2026-10-17）

> 来源：House2Home 官网各页面、社工转介表单（Google Form）、捐赠者表单（Google Form）、NewsChannel 5 的报道。凡是“推断”的内容都已标出，需要和机构核实。

## 1. 组织概况
- 隶属 **510 Foundation**（501(c)(3)），**全部由志愿者运营**。前身叫 “Cheryl's List”，2013 年起源于 First Church of the Nazarene 的一个主日学班级。
- 使命：为**刚脱离无家可归状态、住进新家的人**提供**全新的床**和八成新的家具、家居用品，免费送货上门并布置好房间。
- 规模：2,000 多次配送，从 1,500 多户取过捐赠，合作机构 100 多家（都在 Davidson County），每周配送 6 到 8 套公寓（数据较旧）。
- 资源：Dickerson Pike 上一个 4 个库位的仓库、**2 辆厢式货车**；仓库**只在周六 9 点到 12 点开放**。
- 运营工具：**Google Forms、Google Docs，再加一个捐赠者数据库**。官网写明有一位“Google doc manager”负责协调取件和配送团队。
- 最大缺口（官网原话的意思）：**志愿者**，尤其是取件、送货和开货车的人。

## 2. 服务流程

### 需求端：社工转介
1. 社工必须属于某个已登记的机构，**机构编号由 H2H 分配**。
2. 填写 Google Form：
   - 客户姓名、电话、**详细地址**（楼号、门牌）、所在城市和邮编
   - 社工姓名和电话
   - 最近是否无家可归（是/否）
   - **搬入日期**
   - 按房间勾选所需物品：
     - 客厅：沙发、茶几、椅子、台灯、边桌、餐桌椅
     - 厨房：餐桌椅、锅具、餐具、厨房用具
     - 卧室：**床**、五斗柜、床头柜、台灯、毯子、床品
     - 其他：毛巾、浴帘、地毯、装饰品
   - 自由填写其他需要的物品
   - **家庭构成**：男女，以及各年龄段儿童的人数（婴儿到高中）
   - 补充说明：客户情况
3. 表单末尾声明：志愿者人手和资源有限，**不一定能服务每一位转介对象**。

### 供给端：捐赠
1. **捐赠者表单**：
   - 联系方式和地址
   - **用自由文本列出家具**和家居用品
   - **照片要另外发到 Gmail 邮箱**，不在表单里上传
   - 要求**至少提前两周**通知，因为同一批志愿者既要取件也要送货
   - 询问取件日期是否灵活；不灵活就写明最晚日期
2. **自己送到仓库**：只限周六上午 3 小时。
3. **现金捐赠**：主要用来买新床（不收二手床），一套床垫加床架大约 $400 到 $500，一套全新床品大约 $75。
4. **实物认捐**：每月指定一类物品（例如一月锅具、二月浴巾），每月第一个周日送到教会，或者在 Amazon 上买了寄过去。
5. **社区集中取件日**：一位志愿者自发组织过。两个小区一起捐，一辆空车开进去，出来时满满一辆卡车再加两辆 SUV。

### 收与不收（规则很明确，适合交给机器判断）
- **收**：沙发、椅子、双人沙发、茶几和边桌、床头柜、书架；小号书桌和衣柜视需要而定；小到中号的画和装饰品、台灯、钟；**全新**的床品；餐桌椅、锅具、餐具、刀具、盘碗、12 到 16 盎司的杯子、小家电、没有印字的马克杯；毛巾。
- **不收**：二手床、床垫、床架部件、床头板；二手床品；大家电；电视柜；CRT 电视和过时电子产品；**沙发床**；窗帘；衣物；医疗用品；**任何需要维修、重新包面或外观差的物品**。
- 通用要求：没有破损、污渍、宠物损坏；毛巾要洗过，锅具要清洁。

## 3. 痛点

| # | 痛点 | 证据 | 强度 |
|---|---|---|---|
| P1 | **取件要排 2 到 3 周**，捐赠者至少提前 2 周通知 | 官网和表单原文 | ★★★ |
| P2 | **捐赠审核靠人工**：家具清单是自由文本，照片要另外发邮件，志愿者人工判断收不收 | 表单设计本身 | ★★★ |
| P3 | 可能**白跑一趟**：到了现场才发现有污渍、是沙发床、要维修 | 推断，规则写得这么细，说明经常遇到 | ★★ |
| P4 | **库存和匹配靠人脑加 Google Docs**：转介需求和仓库存货没有系统对接 | 官网写明用 Google Docs，并有专人负责 | ★★ |
| P5 | **司机是最大瓶颈**：2 辆车，同一批志愿者既取件又送货 | 官网原文 | ★★★ |
| P6 | **路线没有合并**：社区集中取件效率高很多，但只是偶尔有人自发组织 | 官网案例 | ★★ |
| P7 | **不能服务所有人**，看不到排序规则，社工也不知道进度 | 表单声明；没有进度查询功能 | ★★ |
| P8 | **新床是最大开支**，靠募款 | 官网 | ★★★ |
| P9 | 关键流程**依赖少数志愿者**（Google doc manager） | 组织架构页 | ★★ |
| P10 | 客户的**敏感信息**（地址、电话、家庭构成）存在 Google Forms 里 | 表单字段 | ★★ |

## 4. AI 能加在哪里（按价值和可演示程度排序）

### ① 拍照预审（解决 P2、P3）—— 核心亮点
- 捐赠者直接上传照片。**视觉模型**识别品类、估计尺寸，检查污渍、破损、宠物毛发，对照“收与不收”规则，给出**接收 / 拒收（附原因）/ 转人工**三种结果。
- 拒收时附上替代去处，例如大家电交给 Habitat ReStore。
- 对接 OCI：OCI Generative AI 的视觉模型，或 OCI Vision。
- **人工保留最终决定权**，AI 只做初筛。

### ② 照片自动入库（解决 P4）
- 审核通过的物品自动生成库存卡片：品类、房间、尺寸、成色、照片、所在库位、状态（已认捐 / 在库 / 已分配）。

### ③ 需求与库存匹配（解决 P4、P7）
- 用 LLM 把转介表的勾选项和补充说明转成结构化需求。比如从“客户坐轮椅，住三楼没电梯”里提取限制条件。
- 把**库存和即将取回的认捐物品**拼成每户一套的“家具包”，标出缺口。
- 缺口是床就提示动用现金购买，缺口是小件就自动生成当月 Amazon 认捐清单。
- **服务的先后顺序用透明规则决定**（搬入日期、家庭人数、等待时长），**不交给 AI**。

### ④ 取件和配送排程（解决 P1、P5、P6）
- 按地理位置和日期，把取件和配送**合并成每辆车每天的路线**，把偶尔组织的“社区集中取件日”变成系统常规功能。
- 路线优化用 OR-Tools 等算法；LLM 只负责生成给志愿者司机看的任务说明。
- 量化目标：每趟车平均处理件数、取件等待天数。

### ⑤ 给社工和客户的进度通知（解决 P7）
- 自动通知“已受理 / 已配齐 / 预计送达时间”；支持多语言短信。

### ⑥ 影响报告（解决 P8）
- 自动统计：免于填埋的吨数（按品类估重）、配齐的户数、儿童人数。
- OCI GenAI 生成给基金会和捐款人的影响报告和故事，**直接帮他们筹钱买床**。

## 5. 黑客松 MVP 建议
- **必做**：① 拍照预审 → ② 自动入库 → ③ 匹配成“家具包”，加一个仪表盘
- **加分**：④ 一键生成“社区集中取件日”路线；⑥ 影响报告
- **Demo 故事线**：社工提交一户需求（单亲妈妈、两个孩子、下周入住）→ 三位捐赠者拍照，其中一张沙发床被 AI 拒收并说明原因 → 系统拼出家具包，缺两张床，提示动用募款 → 生成周六的合并路线 → 最后显示影响数据：多少吨免于填埋、几户配齐
- **扩展路径**：全美各城市都有类似的家具银行（furniture bank）。先在 House2Home 试点，再推广到其他机构；规则配置可以按机构定制。

## 6. 需要找 House2Home 或 mentor 核实的问题
1. 最大的瓶颈是**司机和车**、**仓库空间**，还是**收到的东西不对路**？
2. 每月大约收到多少份转介？有多少最后没能服务到？
3. 白跑一趟（到现场才发现不能收）的情况有多频繁？
4. 现在怎么决定先服务谁？
5. 愿意用新工具吗？还是更希望继续用 Google Forms，只在后台加一层智能处理？
